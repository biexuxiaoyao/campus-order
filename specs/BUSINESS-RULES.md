# BUSINESS-RULES — 核心业务规则

## 1. 库存管理

```
下单: available_stock -= quantity  (预占, 乐观锁 version 字段)
支付成功: 预占确认 (无需额外操作)
支付超时/取消: available_stock += quantity (释放)
手动取消(待支付): 释放预占
商家取消(已支付, 原因=菜品售罄): 释放预占
商家取消(已支付, 原因=用户要求): 不释放
```

- 超卖防护: `WHERE version = ? AND available_stock >= ?`, 重试 ≤3 次
- 代表下单: 支付前二次校验库存
- 拼单截单: 缓冲 30s → 已支付合并, 未支付取消+释放
- 预约取餐: 下单时预占, 取餐日凌晨确认扣减

## 2. 优惠计算引擎

### 计算顺序(不可更改)

```
订单原价(各OrderItem.price × quantity求和)
  → 应用折扣规则(按优先级, 不可叠加取最高, 可叠加依次计算)
  → 折扣后金额
  → 应用优惠券(自动匹配最优券, 用户可手动切换)
  → 券后金额
  → 应用积分抵现(用户选择, N积分=1元, 有最低抵扣门槛)
  → 最终支付金额
  → 微信支付/余额支付补足
```

### 折扣规则

- 条件: 金额/份数/品类/菜品/时段/首次下单/团单专属
- 动作: 打折/减钱/赠积分/免配送费(delivery激活时)/赠菜品(默认规格, 消耗库存)
- 团单: 折扣按每人子订单独立计算
- 首次下单: `该userId在当前租户下已支付且未退款的订单数 = 0`

### 优惠券

- 满减券: 券后金额 ≥ 门槛才可用
- 折扣券: 打N折, 最高减Y元
- 商品券: 指定商品¥0加入订单, 消耗库存
- 券后不退还, 退款按券后实付分摊

### 积分抵现

- 先扣积分 → 不足部分微信补足(不支持余额+积分组合)
- 退款: 积分退积分, 微信退微信
- 月上限: 分享积分 ≤500/月, 同设备新用户不计

## 3. 退款规则

| 场景 | 规则 |
|---|---|
| 全额退款 | 订单金额全额原路返回 |
| 部分退款 | 指定菜品按原价退, 优惠按比例分摊, 余额不足门槛时优惠重算 |
| 支付来源 | 微信→退微信, 个人余额→退个人, 公司储值卡→退公司 |
| 优惠券 | 已使用不退还 |
| 时效 | 支付成功24h内可申请(商家可调), 超时入口隐藏 |
| 次数 | 最多2次, 第二次被拒标记"争议中" |
| 审批 | 老板审批, 需二次密码确认(30min内免再次输入) |

## 4. 订单超时

| 事件 | 默认 | 配置项 |
|---|---|---|
| 提交后未支付 | 15分钟自动取消 | 商家可配 |
| 支付后商家未确认 | 10分钟自动确认/退款(按开关) | 商家可配 |
| 待取餐→已完成 | 营业结束时自动完成 | 系统固定 |
| 购物车 | 24小时自动清空 | 系统固定 |

## 5. 编号规则

| 类型 | 格式 | 示例 |
|---|---|---|
| 个人订单号 | `{YYYYMMDD}{HHmmss}{6位随机}` | `2026061714320918A7F2` |
| 取餐号 | `A{3位自增}` (每日重置) | `A001` |
| 团单号 | `G{YYYYMMDD}{HHmmss}{4位随机}` | `G20260617143209A7F` |
| 团单子编号 | `{取餐号}-{序号}` | `A005-1` |

## 6. 并发控制

- **库存扣减**: 乐观锁(version), 重试3次
- **订单状态变更**: 乐观锁(version), 冲突提示刷新
- **截单**: 30s缓冲窗口, 期间禁止新加入, 等待支付完成
- **支付回调 vs 超时取消**: 取消前先查微信订单状态
- **批量确认 vs 自动取消**: 批量确认跳过已取消的订单

## 7. 时间规则

- **服务端时区**: UTC+8
- **商家时区**: BrandConfig中配置, 用于签到重置/营业时间判断
- **"今日"定义**: 自然日 00:00:00 ~ 当前时刻
- **营业结束**: 打烊前15分钟停止新即时单, 可预约次日
