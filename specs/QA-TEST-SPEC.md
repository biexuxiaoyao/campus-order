## 1. 测试策略

### 1.1 测试层次

```
┌─────────────────────────────────────────┐
│            E2E 端到端测试               │
│   (完整业务流程: 小程序→API→管理后台)     │
├─────────────────────────────────────────┤
│         集成测试 (模块间交互)             │
├─────────────────────────────────────────┤
│     API 接口测试 (每个端点独立验证)       │
├─────────────────────────────────────────┤
│   单元测试 (Service/Util 逻辑)           │
└─────────────────────────────────────────┘
```

### 1.2 测试优先级

| 优先级 | 范围 | 说明 |
|--------|------|------|
| **P0** | base 模块全部功能 + 支付核心流程 | 阻塞发布 |
| **P1** | group-meal / discount / points / coupon / prepaid / printer / push-notify | 影响核心售卖功能 |
| **P2** | 高级报表 / 堂食 / 外卖 / 企业认证 | V2.0 范围，V1.0 仅验证入口不存在 |

### 1.3 测试方法

| 方法 | 工具 | 覆盖目标 |
|------|------|---------|
| 单元测试 | Jest + ts-jest | Service 层逻辑 ≥ 70% |
| API 测试 | Supertest + Jest | 全部 122 端点 |
| E2E 测试 | Supertest E2E | 核心业务流程 |
| 管理后台测试 | 手动 + Playwright (可选) | 14 页面 |
| 小程序测试 | 微信开发者工具 + 真机 | 12 页面 |
| 性能测试 | k6 / autocannon | 关键接口 QPS |

```bash
cd server && npm run start:dev

cd admin-web && npm run dev
```

## 7. 集成测试场景

### 7.1 完整点餐流程 (P0 冒烟)

```
用户打开小程序
  → 微信自动登录
  → 拉取品牌配置 (名称/Logo/主题色)
  → 浏览菜品列表 (分类筛选/搜索)
  → 进入菜品详情 (查看图片/SKU规格)
  → 选择规格 → 加入购物车
  → 购物车查看 (价格/数量)
  → 去结算 (选择取餐时间/备注/支付方式)
  → 提交订单 → 预占库存
  → 微信支付 → 支付成功
  → 订单状态 → "已支付"
  → 商家管理后台收到新订单 (语音播报)
  → 商家确认接单 → 状态 "已确认"
  → 商家开始制作 → 状态 "制作中"
  → 商家完成备餐 → 状态 "待取餐" (取餐号生成)
  → 用户收到订阅消息 (备餐完成)
  → 用户到店取餐 → 商家标记 "已完成"
  → 用户评价 / 再来一单
```

### 7.2 拼单完整流程 (P0)

```
发起人在菜品详情选择商品
  → 发起拼单 (设置截止时间/条件/最低金额)
  → 生成团单号 + 分享卡片
  → 分享到微信群
  → 同事 A/B/C 点击卡片 → 加入拼单 (各自选餐支付)
  → 截止时间到 (或发起人手动截单)
  → 30s 缓冲 → 已支付子订单合并
  → 生成主订单 → 推送商家
  → 商家接单 → 团单汇总小票打印
  → 统一备餐 → 发起人到店取餐 (使用团单取餐号)
```

### 7.3 退款完整流程 (P0)

```
用户申请退款 (选择退款菜品/原因)
  → 订单状态 → refunding
  → 商家管理后台收到退款审批 (老板角色)
  → 老板输入密码二次确认
  → 审批通过 → 调用微信退款 API
  → 退款到账 → 状态 → refunded
  → 用户收到退款到账通知
  → 优惠券不退还 / 积分原路退回 / 库存释放
```

### 7.4 商家入驻流程 (P1)

```
平台管理员创建 Tenant
  → 填入 appId / name / 购买模块
  → 系统生成初始 admin 账号
  → 商家登录管理后台 → 首次强制修改密码
  → 引导: 上传 Logo → 设置营业时间 → 创建分类 → 添加菜品 → 配置支付
  → 小程序从"筹备中"切换为正常菜单页
```

### 7.5 多租户隔离测试 (P0)

```
商家 A 上传菜品 → 商家 B (不同 tenant_id) 不可见
商家 A 的品牌配置 → 商家 B 拉取到自己的配置
商家 A 的用户订单 → 商家 B 管理后台不可见
商家 A 上传的图片 → 商家 B 无法访问 (OSS 目录隔离 / 本地路径隔离)
```

### 7.6 模块购买/关闭联动 (P1)

```
P 端分配模块 → B 端管理后台菜单即时刷新
P 端关闭模块 → 小程序端功能入口消失 / 路由不可访问
packager 按购买清单物理删除未购模块
```

| RISK-004 | **packager 无混淆** | package.json 中无 `javascript-obfuscator` 依赖 | 按 PRD 要求实现混淆流水线 |
| RISK-005 | **packager 水印 transform 是死代码** | `transforms/inject-watermark.ts` 未在任何地方调用 | 删除或集成到流水线 |
| RISK-006 | **packager 映射重复** | `manifest.ts` 和 `strip-imports.ts` 中有两套模块→路径映射 | 统一为单一映射源 |
| RISK-007 | **审计日志覆盖不全** | AuditInterceptor 仅在成功响应时记录 | 失败的写操作也可能需审计 |
| RISK-008 | **购物车无服务端库存校验** | addItem 时不检查 SKU 可用库存 | 下单时校验，购物车阶段可加入超量商品 |
