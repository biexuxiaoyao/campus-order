# STATE-MACHINES — 状态机

## 1. 订单状态机

```
                  ┌── 超时自动取消(恢复库存)
                  │
  待支付 ────────┤
  (pending)      └── 用户手动取消(恢复库存)
     │
     │ 支付成功(微信回调)
     ▼
  已支付 ────────┬── 用户取消(恢复库存)
  (paid)         ├── 商家取消(需选原因, 菜品售罄→恢复库存)
                 └── 申请退款 → 退款中(refunding)
     │                              │
     │ 商家确认                      ├── 商家同意 → 已退款(refunded)
     ▼                              └── 商家拒绝 → 回到退款前状态
  已确认
  (confirmed)
     │
     │ 商家点"开始制作"
     ▼
  制作中 ←── 商家拒绝退款后回到此状态
  (cooking)
     │
     │ 商家点"完成备餐"
     ▼
  待取餐 ←── 营业结束自动完成
  (ready)   商家手动标记已取餐
     │
     └──→ 已完成(completed)
```

**状态变更规则**:
- 所有状态变更使用乐观锁(`version`字段)，冲突时返回 `ORDER_STATUS_CONFLICT`
- "已完成"状态的订单在支付成功后 24h 内仍可申请退款
- 退款申请最多 2 次，第二次被拒标记"争议中"

## 2. 团单状态机

### 拼单模式
```
  拼单中(pooling) ──→ 已截单(closed) ──→ 已合并提交(merged)
     │                    │                    │
     ├─ 发起人取消         │ 发起人截单/        └─→ (生成主订单,
     ├─ 无人参与           │ 截止时间到          跟随订单状态机)
     └─ 全员支付失败(B)    │ 自动截单
        ↓                  ↓
     已取消(cancelled)    [截单缓冲30s:
                         禁止新加入,
                         等待支付完成,
                         支付成功→合并,
                         支付失败→取消]
```

### 代表下单模式
```
  已创建(created) ──→ 已提交(submitted) ──→ (生成订单,
                                             跟随订单状态机)
```

**子订单规则**:
- 拼单中参与者可修改/取消自己的子订单
- 截单后子订单锁定
- 截单后合并生成一个主订单推送给商家
- 主订单使用团单号作为取餐号，子订单保留独立编号(A005-1, A005-2...)

## 3. 桌号状态机（堂食，V2.0）

```
  空闲(idle) ──→ 占用(occupied) ──→ 已结账待清(to_clean)
    ▲                │                      │
    │                │ 多人扫码自动加入      │ 服务员清桌
    └────────────────┴──────────────────────┘
```

## 4. 商家状态机

```
  审核中 → 已开通(active) ──→ 已到期(expired) ──→ 已注销(deleted)
               │                    │
               │ 续费               │ 30天内可恢复
               └────────────────────┘
```

## 5. 支付状态机

```
  待支付 ──→ 支付中 ──→ 支付成功
               │
               └── 支付失败 → 待支付(重试)
               └── 支付超时 → 已取消
```

**并发防护**: 定时任务取消前先查微信订单状态，乐观锁更新。
